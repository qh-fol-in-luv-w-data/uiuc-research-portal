# Plan 2b — Research Assistant Backend (`POST /api/chat`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer questions about UIUC research from the portal's own records, with cited sources, streamed to the existing assistant UI. Both required questions must be answered correctly:
- "What are the most recent UIUC papers on AI in war conflict?"
- "Which faculty members work on Computer Vision in Healthcare?"

**Architecture:** Three stages, in `apps/api/app/chat/`:
1. **Understand** (LLM, JSON). The finetuned `uiuc-qu:4b` produces a search plan, using the same prompt and schema it was trained on (`qu.py`, copied from `finetune/qu.py`), with `format` = JSON schema and `think: false`. Fallback chain: model missing → generation model with few-shot; timeout or unusable plan → rule parser.
2. **Retrieve** (deterministic SQL + numpy). Papers: hybrid full-text ∪ vector candidates, RRF fusion, concept-group AND filter (full-text match OR cosine ≥ τ per group), date filter, sort. Faculty: weighted keyword-IDF + embedding + related-paper evidence.
3. **Generate** (LLM, text). `qwen3:4b-instruct-2507` writes a short answer from numbered sources and cites them. Invalid `[n]` are removed before `done`.

The router streams SSE events `plan → sources → token* → done | error`, matching `apps/web/src/lib/sse.ts`.

**Tech stack:** FastAPI StreamingResponse, httpx (async) to Ollama `/api/chat` and `/api/embed`, psycopg pool, pgvector, numpy.

**Spec:** `docs/superpowers/specs/2026-11-16-uiuc-research-portal-design.md` §7 (rev 2). Benchmarks: `finetune/results/bench_native.jsonl` (2026-11-19).

## Global Constraints

- Models (env): `OLLAMA_QU_MODEL=uiuc-qu:4b`, `OLLAMA_CHAT_MODEL=qwen3:4b-instruct-2507-q4_K_M`, `OLLAMA_EMBED_MODEL=bge-m3`. The local `qwen3:4b` is the Thinking-2507 build and leaks reasoning into answers with `think:false`, so it is not used.
- `uiuc-qu:4b` runs with the training prompt (`qu.build_messages`, zero-shot), `think:false`, `format=qu.SCHEMA`, temperature 0, timeout 20 s.
- Retrieval never calls an LLM. Every parameter lives in `apps/api/app/chat/config.py` (τ, k_rrf=60, candidate pool 200, faculty weights 0.4/0.3/0.3, K related papers 50, outlier/duplicate exclusion).
- Sources are numbered 1..n in the order shown. The answer may cite only those numbers.
- `out_of_scope`: no retrieval, fixed polite reply, no LLM call.
- Ollama unreachable → HTTP 503 JSON `{error, detail}` before streaming. Mid-stream failure → `error` event.
- Commits under the user's name only (no co-author lines).

## File Structure

```
apps/api/app/chat/__init__.py
apps/api/app/chat/qu.py          copy of finetune/qu.py (training contract); finetune/ keeps its own copy for the GPU server
apps/api/app/chat/config.py      retrieval parameters + model names from env
apps/api/app/chat/ollama.py      async client: chat_json(), chat_stream(), embed()
apps/api/app/chat/rules.py       rule-based plan parser (fallback)
apps/api/app/chat/understand.py  understand(question, history, today) -> (plan, source: "model"|"fewshot"|"rules")
apps/api/app/chat/retrieve.py    search_papers(plan, qvec) / search_faculty(plan, qvec, papers) -> ranked hits with evidence
apps/api/app/chat/answer.py      build_sources(), build_prompt(), clean_citations()
apps/api/app/routers/chat.py     POST /api/chat SSE
apps/api/api_tests/test_chat_*.py
eval/queries.yaml                required questions + sanity queries with gold ids
eval/run.py                      retrieval recall@k per query, citation validity, latency (`make eval`)
```

### Task 1: Contract + rule parser + understand()
- [ ] Copy `finetune/qu.py` → `app/chat/qu.py`.
- [ ] Failing tests (`test_chat_understand.py`, fake Ollama):
  - The model's JSON is used when valid.
  - Invalid JSON or a 20 s timeout falls back to the rules.
  - "model not found" (404) falls back to few-shot on the chat model.
  - Rules: "most recent … on X in Y" → sort recent, groups [X],[Y]; "which faculty … work on …" → faculty intent; "most cited" → cited.
- [ ] Implement, pass, commit.

### Task 2: Paper retrieval
- [ ] Failing tests (`test_chat_retrieve.py`, seeded DB with hand-set embeddings):
  - A work matching only one concept group is excluded.
  - A work matching a group only by vector (cosine ≥ τ) is kept.
  - `sort=recent` orders by date among kept works and excludes future dates.
  - Outliers and duplicates are never returned.
- [ ] SQL: candidates = FTS top 200 (`websearch_to_tsquery` OR of all terms) ∪ vector top 200; one query returns, per candidate, its FTS rank, vector rank and per-group FTS match + group cosine.
- [ ] Commit.

### Task 3: Faculty retrieval
- [ ] Failing tests: a faculty member matching both groups outranks one matching one group; IDF favours rare keywords; evidence lists matched keywords and up to 2 related papers.
- [ ] Faculty rows (keywords, embedding, links) are cached in memory at startup (999 rows). The IDF table is built once.
- [ ] Commit.

### Task 4: Answer + SSE router
